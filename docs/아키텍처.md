# 큐알포스트 (QRPost) — 아키텍처 설계

> 작성일: 2026-08-08 / 기획서: qr-beam-app.md

## 1. 전체 구조 원칙

- **2-레이어**: 플랫폼 중립 코어(Swift Package) + 앱(iOS/iPadOS 유니버설). 코어는 UIKit/AVFoundation/SwiftUI를 절대 import하지 않는다 → macOS(Phase 2) 이식 시 코어 재사용.
- **디자인 패턴**: SwiftUI + **MV 패턴** (@Observable 모델, ViewModel 계층 없음). 1인 개발 규모에 TCA/VIPER는 과잉.
- **동시성**: Swift Concurrency. 수신 세션은 actor (Vision 콜백이 백그라운드 스레드에서 옴), UI 상태는 @MainActor @Observable.
- **의존성**: 외부 라이브러리 0개 (qrdrop과 동일 철학). QR 생성도 자체 비트 매트릭스 인코더 (팀 qrdrop의 QRCodeEncoder 이식, 사용 협의 완료).

## 2. 코어 패키지: QRPostCore

### Package.swift
```swift
// swift-tools-version: 5.10
import PackageDescription

let package = Package(
    name: "QRPostCore",
    platforms: [.iOS(.v17), .macOS(.v14)],
    products: [.library(name: "QRPostCore", targets: ["QRPostCore"])],
    targets: [
        .target(name: "QRPostCore"),
        .testTarget(name: "QRPostCoreTests", dependencies: ["QRPostCore"]),
    ]
)
```

### 모듈 구조
```
QRPostCore/
├── Package.swift
├── Sources/QRPostCore/
│   ├── Fountain/
│   │   ├── LTEncoder.swift          # 블록 → 파운틴 패킷 무한 생성
│   │   ├── LTDecoder.swift          # 패킷 수집 → 벨리프 전파 복원
│   │   └── DegreeDistribution.swift # Robust Soliton 분포
│   ├── Wire/
│   │   ├── Packet.swift             # 패킷 = 헤더(fileID, seed, K, 크기) + 페이로드
│   │   ├── FrameCodec.swift         # 패킷 ↔ 바이트 직렬화
│   │   └── CRC32.swift
│   ├── Chunking/
│   │   └── FilePackager.swift       # 파일 → 메타(이름·크기·타입) + 고정 블록 분할
│   ├── QR/
│   │   ├── QRBitMatrixEncoder.swift # 바이트 → QR 비트 매트릭스 (버전 1–40)
│   │   └── QRCapacity.swift         # 버전×EC레벨별 용량 테이블
│   ├── Session/
│   │   ├── SendSession.swift        # 전송 상태머신: nextFrame() → 비트 매트릭스
│   │   └── ReceiveSession.swift     # actor. ingest(bytes) → 진행률/완료 이벤트
│   └── Support/
│       └── SplitMix64.swift         # 결정적 PRNG (송수신 시드 동기화)
└── Tests/QRPostCoreTests/
```

### 핵심 설계 결정
- **코어는 이미지가 아니라 `QRBitMatrix`(Bool 2차원 배열)를 출력** — 렌더링(CGImage/Canvas)은 앱 레이어. 코어가 100% 순수 로직이 되어 `swift test`만으로 전부 검증 가능.
- **수신 입력도 순수 바이트** — 카메라·Vision은 앱에 있고, 코어의 `ReceiveSession.ingest(_ payload: Data)`는 QR에서 뽑은 바이트만 받는다. 즉 "화면·카메라 없이" 송신기 출력을 수신기에 직접 연결하는 통합 테스트가 가능.
- **모든 패킷은 자기완결적**: 헤더에 fileID·시드·블록수·파일크기 포함 → 순서 무관, 중간 진입 가능, 프레임 유실 무시.
- **파일명/타입 메타데이터**는 전용 메타 패킷으로 주기적 삽입.

### 전송 파라미터 (프로토타입에서 실측 후 확정)
| 파라미터 | 초기값 | 비고 |
|---|---|---|
| QR 버전 | 폰 송신 11–15 / 패드 20± | EC 레벨 L |
| 블록(페이로드) 크기 | 300–500B | 헤더 ~24B 별도 |
| 프레임레이트 | 12fps | 10–15 사이 튜닝 |
| 예상 실효 속도 | 폰→폰 15–30KB/s 가정 | 2단계에서 실측 |

## 3. 앱 구조: QRPost (iOS/iPadOS 유니버설)

```
QRPost/
├── App/
│   ├── QRPostApp.swift          # @main
│   └── RootView.swift           # 보내기/받기 2탭 (설정 없음)
├── Features/
│   ├── Send/
│   │   ├── SendView.swift       # 파일 선택 → 예상시간 → 재생
│   │   ├── SendModel.swift      # @Observable. SendSession 소유
│   │   ├── QRStreamView.swift   # TimelineView/CADisplayLink로 비트매트릭스 렌더
│   │   └── CompressionPicker.swift # 사진 압축 옵션 + 예상시간
│   ├── Receive/
│   │   ├── ReceiveView.swift    # 카메라 프리뷰 + 진행률 오버레이
│   │   ├── ReceiveModel.swift   # @Observable. ReceiveSession 소유
│   │   └── CameraController.swift # AVFoundation + Vision → Data 콜백
│   └── Result/
│       └── ReceivedFileView.swift # 저장(사진앱/파일앱)·공유
├── Services/
│   ├── ScreenGuard.swift        # 송신 중 밝기 최대 + isIdleTimerDisabled
│   ├── FileSaver.swift          # PHPhotoLibrary / FileManager 분기
│   └── Haptics.swift
├── Debug/
│   └── MetricsView.swift        # DEBUG 전용: fps·유니크 패킷·중복률·KB/s
└── Resources/
```

- 모델 소유 규칙: View는 상태를 소유하지 않고 `SendModel`/`ReceiveModel`(@Observable)을 @State로 루트에서 생성해 내려보냄.
- 코어 연결: Xcode에서 로컬 Swift Package로 참조 (File > Add Package Dependencies > Add Local).

## 4. 테스트 전략

### 4-1. 코어 유닛 테스트 (Swift Testing, 커버리지의 중심)
| 테스트 | 검증 내용 |
|---|---|
| `LTRoundTripTests` | 랜덤 데이터 인코딩→디코딩 원본 일치 (0B, 1B, 블록경계±1, 1KB, 1MB 등 크기 파라미터화) |
| `PacketLossTests` | 패킷 30/50/70% 무작위 유실 + 순서 셔플에도 복원 성공, 필요 패킷 수 오버헤드 계수 측정 |
| `DeterminismTests` | 동일 시드 → 동일 패킷 시퀀스 (기기 간 재현성 보장) |
| `WireFormatTests` | 직렬화 왕복 일치, 손상 패킷(비트 플립) CRC 거부 |
| `DegreeDistributionTests` | Robust Soliton 분포 통계적 정합성 |
| `QRBitMatrixTests` | 버전별 용량 준수, 고정 벡터 대조(외부 디코더로 사전 검증한 정답 매트릭스) |
| `FilePackagerTests` | 메타데이터 왕복, 경계 크기 파일 |
| `EndToEndCoreTests` | 파일 → SendSession 프레임 스트림 → (바이트 직결) → ReceiveSession → 파일 해시 일치 |

실행: `swift test` (패키지 단독, 시뮬레이터 불필요, CI에서 초 단위 실행).

### 4-2. 앱 통합 검증
- **화면→카메라 루프 실기기 테스트**: 자동화 불가 영역. 반복 가능한 측정 프로토콜을 문서화(고정 거리 20cm, 밝기 최대, 표준 테스트 파일 100KB/1MB/5MB)하고 Debug/MetricsView로 실효 KB/s·중복률 기록.
- **기기 매트릭스**: 폰→폰(기준 성능), 패드→폰(최고 속도), 폰→패드. 각 조합 3회 측정 평균.
- **XCUITest**: 스모크만 (앱 실행 → 두 탭 진입 → 크래시 없음). UI 테스트에 과투자하지 않음.

### 4-3. CI (선택, 저비용)
- GitHub Actions: push 시 `swift test` (macOS 러너) + SwiftLint. 앱 빌드는 로컬.

## 5. 구현 마일스톤 (코어 → 검증 → 제품화)
1. **패키지 골격**: Package.swift + Support(CRC32, SplitMix64) + 테스트 셋업
2. **파운틴 코드**: LT 인코더/디코더 + RoundTrip/Loss/Determinism 테스트
3. **와이어 포맷 + 패키저**: Packet/FrameCodec/FilePackager + EndToEndCore 테스트
4. **QR 인코더**: qrdrop QRCodeEncoder 이식 + 고정 벡터 테스트
5. **앱 골격 + 송신**: QRStreamView 렌더링 (실기기에서 스캔 가능 확인)
6. **수신**: CameraController + ReceiveSession 연결 + 저장
7. **실측 & 튜닝**: MetricsView로 기기 매트릭스 측정 → 파라미터 확정 → UI 폴리싱
