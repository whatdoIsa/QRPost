# 프로젝트: 큐알포스트 (QRPost)

> 작성일: 2026-08-08 / 상태: 기획 확정 단계

## 📋 프로젝트 개요

### 기본 정보
- **프로젝트명**: **큐알포스트** (영문/개발명: QRPost) — 2026-08-08 확정, 한국 스토어 동명 앱 없음 확인
- **스토어 등록명**: "큐알포스트 - 화면으로 파일 전송" / 키워드: QR, QR포스트, QR전송, 파일전송, 사진전송
- **설계 문서**: [qrpost-architecture.md](qrpost-architecture.md)
- **개발자**: 정송헌 (Dean, Arcseed)
- **플랫폼**: iOS + iPadOS (유니버설, Phase 1) → macOS (Phase 2)
- **기술 스택**: Swift / SwiftUI, AVFoundation + Vision(수신), CADisplayLink(송신), LT 파운틴 코드
- **기술 기반**: 팀 내 qrdrop 엔진 (LT Fountain + QR 인코더, Shared 모듈) — 사용 협의 완료
- **제품 관계**: qrdrop과 별도 브랜드의 신규 앱. 코어 엔진은 공유 Swift Package로 추출해 양쪽에서 사용

### 핵심 가치 제안 (30초 피치)
> 화면을 보여주고 카메라로 찍으면 파일이 건너간다. 페어링 없음, 연락처 교환 없음, 계정 없음, 서버 없음 — 전송되는 장면이 눈에 보이는 유일한 전송 앱.

### 포지셔닝 결정 사항
- ❌ "오프라인 대안" 포지셔닝 폐기 — 요즘 사용자에게 네트워크 부재는 실제 문제가 아님
- ✅ **"Show & Send"**: 연결 절차 제로 — 보여주고 찍으면 끝
- ✅ **무흔적**: 서버·계정·연락처를 거치지 않는 프라이버시 (기술 구조상 자동으로 성립)
- ❌ 감성/손편지 프레이밍 하지 않음 — 담백한 도구 앱 (TOSS 스타일 미니멀). 전송 장면의 신기함은 꾸미지 않아도 그 자체로 성립

## 🎯 타겟 사용자

### 주요 페르소나
- **1차**: 10~20대. 신기한 인터랙션을 찍어서 공유하는 유저 — 친구끼리 사진·밈 주고받는 상황
- **2차**: 연락처를 주기 애매한 상대와 파일을 주고받아야 하는 사람 (일회성 만남, 모임, 행사)

### 사용 시나리오
- 친구와 마주 앉아 방금 찍은 사진을 "쏘는" 놀이
- 처음 본 사람에게 번호 교환 없이 사진 전달
- 회사 기기·관리 기기 등 AirDrop이 막힌 환경 (부가 시나리오, 전면에 내세우지 않음)

## 🔥 핵심 기능

### Must Have (MVP)
1. **보내기**: 파일 선택(사진·영상·모든 파일) → 파운틴 인코딩 → QR 스트림 화면 재생 (12fps, 밝기 최대 고정, 꺼짐 방지)
2. **받기**: 카메라 캡처 → Vision QR 디코딩 → 실시간 진행률 표시(수신 블록 시각화) → 파일 앱/사진 앱 저장
3. **예상 시간 표시**: 파일 크기 기반 전송 시간을 전송 전에 명시 ("이 사진은 약 40초") — 기대치 관리가 UX의 핵심
4. **양방향 유니버설**: 폰↔폰, 패드↔폰 모든 조합 (한 앱에 송·수신 모두)

### Should Have
- 사진 전송 시 압축 품질 선택 (빠르게/원본에 가깝게 + 각각 예상 시간)
- 여러 파일 ZIP 묶음 전송
- 수신 완료 햅틱·간결한 완료 화면

### Could Have
- 여러 장 사진 일괄 전송 큐
- 전송 히스토리 (기기 로컬에만 저장)

### Won't Have (MVP 제외)
- 네트워크 폴백(하이브리드) — 컨셉 훼손 위험, 보류
- Android — 수신 앱이 필요하므로 iOS 트랙션 확인 후
- macOS — Phase 2 (엔진 공유로 이식 비용 낮음)

## 📱 기기 조합 매트릭스
| 조합 | Phase | 비고 |
|---|---|---|
| 폰 → 폰 | 1 | 가장 느린 조합(작은 화면) — 기준 성능 타깃 |
| 패드 → 폰 | 1 | 큰 화면 = 고밀도 QR = 최고 속도 |
| 폰 → 패드 | 1 | 수신은 화면 크기 무관 |
| 맥 → 폰 | 2 | qrdrop 엔진 이식 |

## ⚙️ 기술 요점
- 실효 속도 25~50KB/s (qrdrop 실측 기준). 스위트 스팟은 5MB 이하, 상한 64MB
- "모든 파일" 지원하되 UI가 크기별 예상 시간을 정직하게 노출 — 큰 파일은 되긴 하지만 권하지 않는 톤
- 코어(청킹·파운틴 코드·와이어 포맷·CRC)를 Swift Package로 분리, 단위 테스트 집중
- 폰→폰 성능 변수: 화면 크기·밝기, 카메라 거리·초점, 주사율 — 실기기 매트릭스 테스트 필수

## 💰 수익화
- **무료 출시 → 트랙션 확인 후 결정**. 바이럴이 생명이므로 초기 마찰 제로
- 추후 후보: 테마/연출 커스텀 IAP, 원본 화질 전송 등 (컨셉을 해치지 않는 범위)

## 🚀 로드맵 (초안)
- **W1-2**: 코어 패키지 (인코딩/디코딩, 테스트) + 폰→폰 기술 검증 프로토타입
- **W3-4**: 송·수신 UI/UX 및 연출, 실기기 성능 튜닝
- **W5-6**: 폴리싱, 아이패드 대응, TestFlight 베타
- **W7+**: 출시 + 전송 장면 쇼츠 중심 마케팅

## ⚠️ 리스크
- **폰→폰 실효 속도 미달**: 프로토타입에서 최우선 검증. 미달 시 QR 버전·fps 튜닝, 최악엔 사진 중심으로 스코프 축소
- **신기함의 유통기한**: 첫 바이럴 후 리텐션 약할 수 있음 — 일상 사용 시나리오(무흔적 전송)로 받쳐야 함
- **쇼츠 데모 대비 기대치 격차**: "고화질 몇 초" 기대로 유입된 유저의 실망 — 예상 시간 정직 노출로 방어
