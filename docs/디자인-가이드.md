# 큐알포스트 — 디자인 가이드 (Apple HIG 기준)

> 작성일: 2026-08-08. Apple Human Interface Guidelines(OS 27 기준 정제본)을 근거로 작성.
> 각 규칙 뒤 괄호는 근거 HIG 문서.

## 1. 구조와 내비게이션

- **탭 2개: 보내기 / 받기.** 탭 바는 내비게이션 전용 — 액션 버튼을 넣지 않는다 (tab-bars).
- 탭 라벨은 한 단어, SF Symbols는 **filled 변형** 사용 — iOS 탭 바는 자동으로 fill을 선택한다 (tab-bars, sf-symbols).
  - 보내기: `arrow.up.circle.fill` / 받기: `qrcode.viewfinder`
- iPadOS에서는 탭 바가 화면 상단에 표시된다. 섹션이 2개뿐이므로 사이드바 전환은 제공하지 않는다 (tab-bars/iPadOS).
- **QR 재생 화면은 풀스크린 모달**로 표시한다 — 모달은 탭 바를 가릴 수 있는 유일한 예외 (tab-bars). 아래에서 위로 올라왔으므로 종료도 아래로 내려가며 닫힌다 — 모션 피드백은 제스처 방향과 일치해야 한다 (motion).
- 설정 화면 없음. 밝기·화면 유지 등은 자동 처리 — "합리적 기본값을 제공해 즉시 시작하게 하라" (onboarding).

## 2. 색상

- **하드코딩 금지, 시맨틱 컬러만 사용** — 시스템 컬러는 릴리즈마다 값이 바뀔 수 있다 (color).
- 액센트: `Color.blue` (라이트 R0 G136 B255 / 다크 R0 G145 B255, 대비 증가 변형 자동 제공).
- 배경: `systemBackground` 계열. 카드 그룹핑: `secondarySystemBackground`.
- 성공: `Color.green`, 중단·오류: `Color.red` (버튼 role로 지정, 직접 색칠하지 않음).
- **색상만으로 상태를 전달하지 않는다** — 진행률은 숫자+바, 완료는 체크마크 심볼+텍스트를 병행 (accessibility, color).
- 대비: 17pt 이하 텍스트 4.5:1 이상, 18pt+ 또는 Bold는 3:1 이상. 라이트/다크 모두 검증 (accessibility).
- **예외 — QR 패널**: QR 모듈은 다크 모드에서도 항상 흰 바탕 + 검은 모듈. 스캐너 대비 확보를 위한 기능적 요구이며, 콘텐츠(데이터)이지 UI 장식이 아니다. 주변 UI는 시맨틱 컬러로 정상 적응.

## 3. 타이포그래피

- **시스템 텍스트 스타일만 사용** (Dynamic Type 자동 지원). 커스텀 폰트 없음 (typography).

| 용도 | 스타일 | 기본(Large) 크기 |
|---|---|---|
| 화면 제목 | Title 2 / 내비게이션 타이틀 | 22pt |
| 파일명, 주요 정보 | Headline (Semibold) | 17pt |
| 본문, 버튼 | Body | 17pt |
| 보조 정보 (크기·속도) | Footnote | 13pt |
| 최소 허용 | — | 11pt (iOS 최소) |

- Ultralight/Thin/Light 웨이트 금지, Regular~Bold만 사용 (typography).
- **AX5(본문 53pt)까지 레이아웃이 깨지지 않아야 한다.** 큰 크기에서 텍스트는 말줄임 대신 줄바꿈; 진행률 행은 세로 스택으로 전환 (typography/Dynamic Type).
- 탭 라벨 등 바 항목은 본문과 함께 커지지 않아도 된다 — 중요 콘텐츠 우선 (typography).

## 4. 레이아웃과 터치

- 모든 컨트롤 최소 히트 영역 **44×44pt** (buttons, accessibility).
- 주요 버튼은 화면 **중하단** — 한 손 그립에서 닿는 위치 (designing-for-ios).
- **풀 블리드 전체 폭 버튼 금지** — 시스템 마진만큼 인셋 (layout/iOS).
- 세이프 에어리어 준수 (Dynamic Island, 홈 인디케이터) (layout).
- iPhone은 세로 우선, iPad는 전 윈도우 크기 대응 — iPad는 자유 리사이즈를 전제로 설계 (layout/iPadOS).

## 5. 화면별 설계

### 5-1. 보내기 홈
- 큰 파일 선택 영역 1개 + 캡션. 컨트롤 최소화 — "온스크린 컨트롤을 제한하라" (designing-for-ios).
- 브랜드 로고 반복 금지 — 상단 타이틀 텍스트로 충분 (branding).

### 5-2. 전송 준비
- 화질 선택지마다 **결과 크기와 예상 시간을 함께 표기** ("280KB · 약 15초"). 선택 상태는 액센트 테두리 + 체크마크 심볼 병행 (색상 단독 금지).
- 프로미넌트(액센트 배경) 버튼은 화면당 1개 — "재생 시작"만. 프라이머리 스타일 (buttons).

### 5-3. QR 재생 (풀스크린)
- 필수 컨트롤은 풀스크린에서도 항상 접근 가능해야 한다 — **"중단" 버튼 상시 노출**, 자동 숨김 금지 (going-full-screen).
- "중단"은 destructive role(빨간 텍스트), 프로미넌트 스타일 금지 — 파괴적 액션에 프라이머리를 주지 않는다 (buttons).
- 상태바 숨김 허용 — 경험을 실질적으로 향상시키는 미디어성 화면에 해당 (layout/iOS). 홈 인디케이터 기본 동작 유지 (going-full-screen/iOS).
- 전송 경과·프레임 정보는 Footnote로 최소 표기. QR 자체가 콘텐츠.
- QR 프레임 전환은 데이터 전송 그 자체이므로 Reduce Motion 대상이 아니다. 단 장식성 애니메이션(펄스 등)은 Reduce Motion 시 제거 (accessibility).

### 5-4. 받기 (카메라)
- **카메라 권한은 받기 탭 최초 사용 시점에 요청** — 앱 실행 시 요청 금지 (privacy).
- 목적 문자열(purpose string): 능동태 완결 문장. 예: `"상대 화면의 QR 코드를 읽어 파일을 받기 위해 카메라를 사용합니다."` (privacy).
- 사전 안내 화면은 불필요 — 받기 탭 진입이라는 맥락이 이유를 설명한다. 만들 경우 버튼 1개("계속"), "허용" 문구 금지 (privacy/pre-alert).
- 진행률은 **확정형(determinate)** — 블록 수를 아는 구조이므로 선형 ProgressView + 수치 병행. "로딩 중" 같은 모호한 문구 금지, "34/53 블록" 처럼 구체적으로 (progress-indicators).
- 인디케이터는 항상 움직여야 한다 — 프레임 수신이 끊기면 "카메라를 화면에 더 가까이 대주세요" 같은 실행 가능한 안내 표시 (progress-indicators).
- **취소 버튼 포함** — 중단해도 부작용 없음 (progress-indicators).
- 진행률 형태는 화면 간 일관 — 선형 바로 통일, 원형과 혼용 금지 (progress-indicators).

### 5-5. 수신 완료
- 완료 확인 표시는 정당 — 파일 전송은 "충분히 중요한 액션" (feedback).
- 체크마크 심볼(`checkmark.circle.fill`, green) + 텍스트 + **성공 햅틱(Notification-success)** 3중 전달 — 색·텍스트·촉각 조합으로 접근성 확보 (feedback, playing-haptics).
- 햅틱은 시스템 의미대로만: 완료=success, 실패=error. 같은 패턴을 다른 의미로 재사용 금지 (playing-haptics).
- 버튼: "확인"(프라이머리) + "공유"(일반, `square.and.arrow.up`) — 동사 기반 라벨 (writing, icons).

## 6. UX 라이팅

- 버튼은 동사로 시작: 파일 선택 / 재생 시작 / 저장 / 중단 (writing).
- 오류는 "무엇이 잘못됐고 어떻게 하는지": `"인식이 끊겼어요. 두 기기를 20cm 정도로 가까이 해주세요."` — 감탄사("앗!") 금지, 비난 금지 (writing).
- "우리"라는 주어 금지. 소유격 최소화 (writing).
- 빈 상태(수신 대기 등)에는 다음 행동 안내 포함 (writing).

## 7. 접근성 체크리스트

- [ ] VoiceOver: 모든 컨트롤에 라벨. QR 재생 뷰는 `accessibilityValue`로 경과 전달, 수신 진행률은 주기적 어나운스, 완료 시 알림
- [ ] 색상 단독 상태 전달 없음 (심볼+텍스트 병행)
- [ ] Dynamic Type AX5 레이아웃 검증
- [ ] 대비 4.5:1 (라이트/다크/대비증가 3모드)
- [ ] Reduce Motion 시 장식 애니메이션 제거
- [ ] 터치 타깃 44×44pt
- [ ] 제스처에는 항상 온스크린 대안 버튼 존재
